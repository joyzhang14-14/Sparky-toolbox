# ask-user 用法

参数格式（最小示例）：
```
ask_user(why="要定接入方式才能写提案", questions=[
  {"question": "接入形式要哪种？", "type": "single", "options": ["做成工具", "只写用法手册"]},
  {"question": "程序装在哪？", "type": "fill", "default": "~/apps/<名>/", "hint": "写绝对路径"}
])
```
- options 是字符串列表，每题 1–3 个、每个 ≤50 字（「其他」程序会自动加）；选项的解释写进 question，不要把选项写成对象。
- why 和 questions 同级（整轮问题一句话的原因），不写进某道题里。

- 普通问题：尽量 ≤4 题，用单选 / 多选，不带备注（notes 不写）。
- 搭建需求（要调 builder 提计划、或 builder 开发中要问需求细节）关键选择没说清时：用填空题（type: fill）从下面的题库挑真不清楚的，
  最多 6 题 + 备注（notes: true）；default 写你的猜测，hint 写填写提示。能从本机查到的自己查，不要问。
- 所有题都可以不答：「无回答」的按你自己的判断做（任务说明另有规定的照任务说明），并在提案 / 交付说明里写明你替他定了什么；预填没改的就是他认可了你的猜测。

题库（question 用标准问法，｜后面是 hint，按需要改写）：
- 用途：谁在什么时候用、解决什么问题？｜举一个调用例子，如「我私信说……，它就……」
- 用什么：本机已有的哪些模型 / 环境 / 路径 / 档位？能不能下载新东西？｜写名字或路径；不清楚可以留空让它自己查
- 输入：主要参数是什么？哪些可选？｜如：图片路径（必填）、风格（可选，默认写实）
- 输出：产物是什么、什么格式、放哪、交回什么？｜如：PNG 放工作目录 media/，交回路径和一句说明
- 外围：主模型能不能看到成品再发？坏输入在哪一步拦？失败了自己重试还是先问你？会变的内容是不是运行时再读？｜只写你在意的几条
- 验收：拿什么真实样本跑？怎样算通过？｜如：用 ~/样例/xx.jpg 跑一遍，出图无水印
- 不要：明确不要的东西？｜功能、依赖、做法都行
- 加到哪：加到哪些任务？｜写任务名；不写就只建不加
